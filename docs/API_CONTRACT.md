# API and CLI Contract Documentation

VidMeta AI does not currently expose an HTTP API. The user-facing contracts are the CLI, the Streamlit UI inputs, and the metadata JSON generated by the LLM.

## CLI

```bash
vidmeta run [app.py] [streamlit flags...]
```

Defaults:

- Launches `app.py`.
- Disables Streamlit usage telemetry.
- Sets `server.maxUploadSize` from `VIDMETA_MAX_UPLOAD_MB`, default `2048`.
- Sets `server.maxMessageSize` from `VIDMETA_MAX_MESSAGE_MB`, defaulting to the upload limit.

Examples:

```bash
vidmeta run
VIDMETA_MAX_UPLOAD_MB=4096 vidmeta run app.py
vidmeta run app.py --server.port 8502
```

## UI input contract

Single video mode accepts either:

- Browser upload: `.mp4`, `.mov`, `.avi`, `.mkv`, `.webm`, `.m4v`.
- Local file path: any readable local file with a supported video extension.

Batch mode accepts:

- A local folder path.
- Files in that folder with supported video extensions.

## Processing contract

For each video:

1. Extract frames with OpenCV.
2. Optionally extract/transcribe audio with `ffmpeg` and Whisper.
3. Send frames plus transcript to the selected LLM provider for analysis.
4. Send the analysis back to the LLM for platform metadata.
5. Parse metadata as JSON.
6. Render and export JSON, CSV, or TXT.

## Metadata JSON contract

```json
{
  "video_summary": "string",
  "content_category": "string",
  "youtube": {
    "title": "string",
    "description": "string",
    "hashtags": ["string"],
    "keywords": ["string"],
    "cta": "string",
    "posting_tip": "string"
  },
  "instagram": {},
  "facebook": {},
  "tiktok": {},
  "linkedin": {}
}
```

Each platform object should contain the same keys as `youtube`.

## Future HTTP API contract

If the project grows beyond Streamlit, add a small local FastAPI service:

```text
POST /api/analyze
GET  /api/jobs/{job_id}
GET  /api/jobs/{job_id}/export.json
GET  /api/jobs/{job_id}/export.csv
```

For the current MIT local release, this HTTP layer is optional.
